# 高性能CRC加速引擎架构设计文档

## 1. 概述

### 1.1 设计目标
- 数据位宽：256bit
- 接口协议：AXI-Stream
- 支持CRC类型：CRC32、CRC32C、CRC64
- 工作模式：On-the-fly计算（流水线处理）
- 系统时钟：1.2GHz
- 目标吞吐率：10GB/s

### 1.2 性能分析
- 理论最大吞吐率：256bit × 1.2GHz = 307.2 Gbps = 38.4 GB/s
- 目标吞吐率：10GB/s
- 效率要求：10/38.4 ≈ 26%（考虑流水线开销和AXI握手，实际可达更高）

### 2.2 接口定义

#### 2.2.1 AXI-Stream Slave接口（输入数据）
- `s_axis_tdata[255:0]`: 256-bit数据
- `s_axis_tvalid`: 数据有效信号
- `s_axis_tready`: 接收就绪信号
- `s_axis_tlast`: 数据包结束标志
- `s_axis_tkeep[31:0]`: 字节有效掩码（可选）

#### 2.2.2 AXI-Stream Master接口（输出CRC结果）
- `m_axis_tdata[63:0]`: CRC结果（CRC32/CRC32C为32bit，CRC64为64bit）
- `m_axis_tvalid`: 结果有效信号
- `m_axis_tready`: 下游就绪信号
- `m_axis_tlast`: 结果包结束标志

#### 2.2.3 控制接口
- `crc_type[1:0]`: CRC类型选择（00=CRC32, 01=CRC32C, 10=CRC64）
- `crc_init[63:0]`: CRC初始值
- `crc_enable`: CRC计算使能
- `crc_reset`: CRC复位（同步复位）

## 3. 关键设计决策

### 3.1 流水线设计
- 采用多级流水线实现On-the-fly计算
- 每级处理256bit数据的一部分
- 流水线深度：3-4级（平衡延迟和面积）

### 3.2 CRC算法选择
- CRC32: 多项式 0x04C11DB7 (IEEE 802.3)
- CRC32C: 多项式 0x1EDC6F41 (Castagnoli)
- CRC64: 多项式 0x42F0E1EBA9EA3693 (ECMA-182)

### 3.3 并行计算策略
- 256bit数据分为多个32bit/64bit块并行处理
- 使用查找表（LUT）或并行CRC计算单元
- 最后合并各块的计算结果

### 3.4 资源优化
- 共享部分计算资源（如LUT）
- 使用多路选择器选择CRC类型
- 优化关键路径以支持1.2GHz时钟

## 4. 性能指标

### 4.1 吞吐率
- 目标：10GB/s
- 在1.2GHz时钟下，每周期处理256bit = 32字节
- 理论峰值：32字节 × 1.2GHz = 38.4 GB/s
- 考虑AXI握手和流水线气泡，实际可达10GB/s以上

### 4.2 延迟
- 流水线延迟：3-4个时钟周期
- 端到端延迟：< 5ns（在1.2GHz下）

### 4.3 资源估算
- LUT: ~5000-8000
- FF: ~3000-5000
- BRAM: ~10-20块（如果使用LUT）
