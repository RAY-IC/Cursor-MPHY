# CRC加速引擎微架构设计文档

## 1. 微架构概述

### 1.1 设计原则
- 流水线化处理，实现On-the-fly计算
- 并行CRC计算单元，充分利用256bit数据位宽
- 低延迟设计，最小化流水线级数
- 资源复用，减少硬件开销

## 2. 详细模块设计

### 2.1 AXI-Stream接口模块 (axi_stream_if)

#### 功能
- 处理AXI-Stream协议握手
- 数据缓冲和流控
- 处理tlast信号，标识数据包边界

#### 接口信号
```verilog
// Slave接口（输入）
input  [255:0] s_axis_tdata
input          s_axis_tvalid
output         s_axis_tready
input          s_axis_tlast
input  [31:0]  s_axis_tkeep

// 内部接口（到CRC引擎）
output [255:0] data_out
output         data_valid
input          data_ready
output         packet_last
```

#### 实现要点
- 简单的直通逻辑，无FIFO（假设CRC引擎总是ready）
- 或使用小FIFO缓冲（2-4级）处理背压

### 2.2 CRC计算引擎核心模块

#### 2.2.1 CRC32计算单元

**算法原理：**
- 多项式：0x04C11DB7
- 256bit数据分为8个32bit块
- 每个块独立计算CRC，然后合并

**流水线结构：**
```
Stage 1: 数据输入和字节序调整
Stage 2: 并行CRC32计算（8个32bit块）
Stage 3: CRC结果合并
Stage 4: 与历史CRC值异或
```

**并行计算单元：**
- 8个CRC32计算器，每个处理32bit
- 使用并行CRC算法（基于矩阵乘法）

#### 2.2.2 CRC32C计算单元

**算法原理：**
- 多项式：0x1EDC6F41
- 结构与CRC32类似，仅多项式不同

#### 2.2.3 CRC64计算单元

**算法原理：**
- 多项式：0x42F0E1EBA9EA3693
- 256bit数据分为4个64bit块
- 4个CRC64计算器并行处理

### 2.3 CRC并行计算算法

#### 2.3.1 理论基础
对于256bit数据D[255:0]，将其分为N个块（CRC32: N=8, CRC64: N=4）

每个块独立计算CRC，然后使用CRC的线性性质合并：
```
CRC(D) = CRC(D7) ⊕ CRC(D6) ⊕ ... ⊕ CRC(D0) ⊕ CRC_prev
```

其中每个块的CRC计算可以表示为：
```
CRC(Di) = (Di << CRC_WIDTH) mod POLY
```

#### 2.3.2 实现方法
- **方法1：查找表（LUT）**
  - 预计算256个可能值的CRC结果
  - 快速但占用BRAM资源
  
- **方法2：并行矩阵乘法**
  - 使用组合逻辑实现
  - 面积较大但延迟小
  
- **方法3：混合方法**
  - 小数据块用LUT，大数据块用矩阵乘法
  - 平衡面积和性能

### 2.4 控制逻辑模块

#### 功能
- CRC类型选择（多路选择器）
- CRC初始值管理
- 使能和复位控制
- 数据包边界检测

#### 状态机
```
IDLE -> CALCULATING -> RESULT_READY -> IDLE
```

### 2.5 结果缓冲模块

#### 功能
- 暂存CRC计算结果
- 处理AXI-Stream输出握手
- 支持背压

## 3. 流水线设计

### 3.1 流水线级数
```
Stage 0: AXI接口接收数据
Stage 1: 数据预处理（字节序、掩码处理）
Stage 2: 并行CRC计算（各块独立计算）
Stage 3: CRC结果合并
Stage 4: 与历史CRC异或，更新状态
Stage 5: 结果输出（AXI接口）
```

### 3.2 流水线控制
- 使用valid/ready握手协议
- 支持流水线暂停（stall）
- 处理数据包边界（tlast）

### 3.3 关键路径优化
- Stage 2的并行CRC计算是关键路径
- 使用寄存器分割长组合路径
- 优化CRC合并逻辑

## 4. 数据路径

### 4.1 数据流
```
AXI输入 -> 数据缓冲 -> CRC类型选择 -> 并行CRC计算 -> 结果合并 -> 
历史CRC更新 -> 结果缓冲 -> AXI输出
```

### 4.2 控制流
```
控制信号 -> CRC类型解码 -> 多路选择器控制 -> 计算单元使能 -> 
结果选择 -> 输出控制
```

## 5. 时序设计

### 5.1 时钟域
- 单时钟域设计（1.2GHz）
- 所有模块同步复位

### 5.2 时序约束
- 输入建立时间：> 0.5ns
- 输出保持时间：> 0.3ns
- 关键路径延迟：< 0.8ns（考虑时钟偏斜和抖动）

### 5.3 流水线平衡
- 各流水线级延迟尽量均衡
- 避免某级成为瓶颈

## 6. 资源估算

### 6.1 CRC32/CRC32C单元
- LUT: ~800 per unit × 8 = 6400
- FF: ~200 per unit × 8 = 1600

### 6.2 CRC64单元
- LUT: ~1500 per unit × 4 = 6000
- FF: ~300 per unit × 4 = 1200

### 6.3 控制逻辑
- LUT: ~500
- FF: ~200

### 6.4 接口逻辑
- LUT: ~300
- FF: ~100

### 6.5 总计
- LUT: ~13200
- FF: ~3100
- BRAM: 0-20（取决于实现方式）

## 7. 优化策略

### 7.1 面积优化
- 共享CRC计算资源（时分复用）
- 使用更小的LUT
- 优化合并逻辑

### 7.2 性能优化
- 增加流水线级数（如果关键路径太长）
- 使用更快的CRC算法
- 优化关键路径

### 7.3 功耗优化
- 时钟门控
- 不使用的计算单元断电
- 数据路径优化
